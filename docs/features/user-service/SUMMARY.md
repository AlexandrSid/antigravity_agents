# User Service — сводка возможности

## Назначение

User Service — контейнеризованное REST-приложение для управления пользователями, их адресами и прямыми родственными связями. Реализация построена на Java 21, Spring Boot 3.3.6, Gradle 8.10.2, Spring Data JPA, Flyway и H2 в TCP-режиме.

Сервис поддерживает:

- создание, чтение, полную замену и мягкое удаление пользователей;
- поиск активного пользователя по идентификатору или нормализованному email;
- получение активных родителей и детей первого уровня;
- нормализацию email, телефона и адреса;
- повторное использование совпадающих адресов;
- активную уникальность email и телефона с возможностью повторного использования после мягкого удаления;
- защиту от недопустимых и циклических родительских связей;
- ошибки в формате RFC 7807;
- автоматическую инициализацию схемы и 1 000 пользователей по 20 адресам через Flyway.

Архитектура разделена на Controller → Service → Repository. HTTP API принимает и возвращает DTO; JPA-сущности наружу не публикуются.

## Публичный HTTP API

Базовый путь: `/api/v1/users`.

- `POST /api/v1/users` — создаёт пользователя. Успех: `201 Created`, заголовок `Location: /api/v1/users/{id}` и сохранённый `UserResponse`.
- `GET /api/v1/users/{id}` — возвращает активного пользователя. Успех: `200 OK`; отсутствующий или удалённый пользователь: `404`.
- `PUT /api/v1/users/{id}` — полностью заменяет данные активного пользователя. Успех: `200 OK`. Отсутствующие или явные `null` в необязательных полях сбрасывают телефон, адрес и родительские связи.
- `DELETE /api/v1/users/{id}` — выполняет мягкое удаление через `is_deleted=true`. Успех: `204 No Content`; физическое удаление не выполняется.
- `GET /api/v1/users/by-email?email={email}` — выполняет точный поиск активного пользователя после приведения email к нижнему регистру.
- `GET /api/v1/users/{id}/family` — возвращает верхнеуровневый JSON-массив из активного пользователя, его активных родителей и активных прямых детей. Рекурсивные предки и потомки не включаются.

### Основные контракты данных

Для создания и замены обязательны `firstName`, `lastName`, прошедшая `birthDate` и синтаксически корректный `email`. Необязательны `phoneNumber`, `address`, `fatherId` и `motherId`.

Телефон нормализуется в E.164 и должен соответствовать `^\+[1-9]\d{6,14}$`. Email сохраняется в нижнем регистре.

Адрес состоит из обязательных `country`, `city`, `street`, `building` и необязательных `apartment`, `postalCode`. Пробелы нормализуются, а идентичность определяется без учёта регистра по всем шести компонентам. Существующие строки адресов не изменяются: пользователь связывается с найденным адресом либо с новой строкой.

В ответах необязательные значения `null` не сериализуются. `childrenIds` всегда присутствует как массив.

## Бизнес-правила

- Email и непустой телефон уникальны среди активных пользователей.
- После мягкого удаления email и телефон можно использовать снова.
- Назначаемые родители должны существовать и быть активными.
- Один пользователь не может одновременно быть отцом и матерью.
- Пользователь не может быть собственным родителем, предком или потомком через создаваемый цикл.
- Мягкое удаление не очищает существующие семейные ссылки.
- Удалённый пользователь может быть якорем семейного запроса, но не включается в результат.
- Проверка возраста родителя при runtime-запросах не входит в текущий объём.

## Ошибки

Ошибки возвращаются как `application/problem+json` и содержат `type`, `title`, `status`, `detail` и `instance`.

- `400 Bad Request` — ошибки валидации, ненормализуемый телефон, некорректный JSON и недопустимые родительские связи.
- `404 Not Found` — пользователь или назначаемый родитель отсутствует либо недоступен по правилам мягкого удаления.
- `409 Conflict` — email или телефон уже принадлежит другому активному пользователю.

Ошибки валидации дополнительно содержат `invalidParams` с именем поля и причиной.

## Конфигурация и запуск

### Предварительные требования

- Java 21 через корректный `JAVA_HOME`;
- Docker Engine или Docker Desktop с Compose v2;
- локальный Gradle Wrapper 8.10.2.

Приложение слушает порт `8080`. Локальная H2 доступна через `jdbc:h2:tcp://localhost:9092/./userservice`; Docker-профиль использует `jdbc:h2:tcp://h2-db:9092/./userservice`. Пользователь БД — `sa`, пароль пустой. Для Compose устанавливается `SPRING_PROFILES_ACTIVE=docker`.

Flyway включён и загружает миграции из `classpath:db/migration`. Hibernate использует `ddl-auto=validate`, а `open-in-view` отключён.

### Команды

Команды ниже воспроизведены из `docs/PROJECT_ENV.md`:

- проверить компиляцию: `.\gradlew.bat testClasses`;
- запустить Unit/Slice-тесты: `.\gradlew.bat test`;
- запустить один тест: `.\gradlew.bat test --tests "{test_class}"`;
- применить миграции: `.\gradlew.bat flywayMigrate`;
- скомпилировать Integration-тесты: `.\gradlew.bat integrationTestClasses`;
- запустить полный Integration/E2E gate: `.\scripts\run-integration-e2e.ps1`;
- запустить локальную БД: `docker compose up -d h2-db`;
- запустить приложение локально: `.\gradlew.bat bootRun`;
- запустить полный Compose-стек: `docker compose up --build`;
- остановить Compose-стек: `docker compose down`.

Перед локальной миграцией или запуском приложения сначала должна быть запущена H2.

### Ограничение доказательств для текущей ревизии

Зафиксированный Integration/E2E PASS относится к более раннему механизму конкурентного разрешения адресов: отчёт упоминает миграцию `V3__serialize_address_resolution.sql`, таблицу блокировки и три миграции. Текущий код использует вычисляемый `addresses.normalized_text`, уникальный индекс `ux_addresses_normalized_text` и повторное чтение после конфликта уникальности; миграция V3 отсутствует, а актуальный интеграционный тест ожидает две версионные миграции.

Следовательно, существующий отчёт **не подтверждает повторный полный Integration/E2E-прогон текущей ревизии**. Кроме того, чекбоксы Секции 2 в `TDD_PLAN.md` остаются незаполненными. Для полного закрытия Documentation Gate требуется, чтобы предшествующая интеграционная стадия повторно выполнила `Run Integration / E2E Gate`, обновила `INTEGRATION_REPORT.md` и зафиксировала актуальные доказательства.
