# Стандарт отслеживания состояния конвейера и межсредовой передачи (Pipeline State & Handoff Standard)

Этот документ определяет единый регламент фиксации прогресса и передачи управления между различными средами разработки (Google Antigravity, Cursor, Claude Code, Windsurf, headless Python-runtime, CI/CD).

---

## 1. Единый источник правды о выполнении: `PIPELINE_STATE.md`

Для каждой разрабатываемой фичи в каталоге `docs/features/{feature}/` создаётся и поддерживается единственный авторитетный артефакт текущего состояния конвейера:
**`docs/features/{feature}/PIPELINE_STATE.md`**

### 1.1. Правила инициализации
1. При первом запуске работы над фичей `{feature}` оркестратор проверяет наличие `docs/features/{feature}/PIPELINE_STATE.md`.
2. Если файл отсутствует, оркестратор:
   - Парсит матрицу выполнения (Секция 2) из активного файла пайплайна (по умолчанию `.ai/pipelines/GREENFIELD_SDLC_PIPELINE.md`).
   - Инициализирует `PIPELINE_STATE.md` по шаблону `.ai/pipelines/templates/PIPELINE_STATE_TEMPLATE.md`.
   - Заполняет список шагов, их роли, гейты и ожидаемые артефакты.
   - Выставляет начальный статус конвейера `INITIALIZED`.

---

## 2. Протокол возобновления работы (The Resume Protocol)

Любой оркестратор в любой среде **ОБЯЗАН** следовать строгому алгоритму запуска:

1. **Проверка существующего прогресса**:
   - Запрещено автоматически перезапускать конвейер с Шага 01, если в `PIPELINE_STATE.md` уже зафиксированы завершённые шаги (`COMPLETED` / `[x]`).
   - Оркестратор сканирует таблицу шагов сверху вниз и находит первый шаг, имеющий статус `PENDING` или `IN_PROGRESS`.
2. **Верификация входов (Input Verification)**:
   - Перед передачей управления субагенту шага оркестратор физически проверяет наличие всех входных артефактов (`Inputs` из матрицы) на диске.
   - Если входной артефакт отсутствует, переход блокируется с фиксацией ошибки: `Missing prerequisite artifact: {path}`.
3. **Фиксация шага в прогрессе**:
   - Оркестратор обновляет поле `Current Step`, переводит статус шага в `IN_PROGRESS`, указывает идентификатор текущей среды (`antigravity`, `cursor`, `claude`, etc.) и время старта.

---

## 3. Критерии перехода состояний шага

Переход шага в статус `COMPLETED` (`[x]`) разрешён **ИСКЛЮЧИТЕЛЬНО** при одновременном выполнении 4 условий:
1. **Физическое наличие артефактов**: все файлы из списка `Outputs` шага созданы на диске и не являются пустыми.
2. **Успешный Quality Gate**: автоматическая проверка (из манифеста `docs/PROJECT_ENV.md`) завершилась с кодом возврата `0` (для `UNIT_RED_PHASE` — компиляция 0, падение тестов строго по ожидаемому `AssertionError`).
3. **Атомарный Git-коммит**: сделан коммит шага вида `feat(step-{id}): {role_name} output finalized`.
4. **Запись в лог аудита**: сделана запись в `docs/features/{feature}/EXECUTION_TRACE.json` и таблице истории `PIPELINE_STATE.md`.

Если Quality Gate провален:
- Шаг остаётся в статусе `IN_PROGRESS (Attempt N/3)`.
- Выполняется откат (`git reset --hard`) к контрольной точке шага.
- Стектрейс ошибки передаётся агенту на повторную попытку.
- При исчерпании 3 попыток статус шага переводится в `BLOCKED`, а конвейер останавливается с запросом вмешательства человека.

---

## 4. Межсредовая передача (Cross-Environment Portability)

Конвейер спроектирован так, чтобы работа могла бесшовно передаваться между разными инструментами:
- **Разработчик может начать Шаг 01 (Architect) в Google Antigravity**, закоммитить изменения.
- **Открыть проект в Cursor**, вызвать оркестратор Cursor: оркестратор читает `PIPELINE_STATE.md`, видит `Step 01 COMPLETED` и мгновенно стартует с **Шага 02 (TDD Planner)**, выбрав модель из `.cursorrules` / `.ai/agents-config.md`.
- **Запустить интеграционные тесты в headless CI / Python-runtime**: рантайм прочитает `PIPELINE_STATE.md` и продолжит с незавершённого шага.

Никакой оркестратор не имеет права стирать историю шагов, выполненных в другой среде.
