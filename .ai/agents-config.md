# Конфигурация агентной системы и маршрутизация LLM

Этот манифест определяет правила выбора и переключения LLM-моделей для каждого агента системы. При работе через IDE оператор или оркестратор перед запуском роли сверяется с этим документом и выбирает модель, соответствующую назначенному профилю.

Документ задаёт только маршрутизацию моделей. Требования и стек берутся из `docs/PRD.md`, архитектурные и функциональные контракты — из `docs/features/{feature}/SPEC.md`, а переменные окружения, команды сборки, тестирования, запуска и очистки — исключительно из `docs/PROJECT_ENV.md`. Запрещено угадывать или дублировать здесь проектные команды и значения конфигурации.

---

## 1. Классификация профилей задач

| Профиль | Назначение и требуемые характеристики | Ключевые требования к LLM |
|---|---|---|
| **`REASONING_HEAVY`** | Глубокий анализ, выявление неопределённостей, архитектурное проектирование и декомпозиция планов контроля качества. | Сильное системное мышление, длинный контекст, устойчивость к логическим противоречиям. |
| **`STRICT_CODEGEN`** | Генерация продуктового кода, модульных и интеграционных тестов строго по спецификациям. | Высокая точность синтаксиса, строгое соблюдение типов и контрактов, отсутствие неподтверждённых предположений. |
| **`FAST_EXECUTION`** | Шаблонная генерация окружения, каркасов типов и служебных артефактов. | Низкая задержка, высокая скорость и точное соблюдение заданной структуры. |

## 2. Матрица привязки шагов к профилям

Нумерация и роли в этой таблице должны точно совпадать с матрицей в `.ai/GREENFIELD_SDLC_PIPELINE.md`.

| Шаг | Роль | Файл правил | Назначаемый профиль | Обоснование выбора |
|:---:|---|---|:---:|---|
| **01** | **Architect** | `.ai/rules/architect.md` | `REASONING_HEAVY` | Проектирование контрактов, схем данных и архитектуры в `docs/features/{feature}/SPEC.md`. |
| **02** | **TDD Planner** | `.ai/rules/tdd-planner.md` | `REASONING_HEAVY` | Декомпозиция спецификации на атомарные TDD-задачи в `docs/features/{feature}/TDD_PLAN.md`. |
| **03** | **Environment Bootstrap** | `.ai/rules/environment-bootstrap.md` | `FAST_EXECUTION` | Детерминированная материализация окружения по `docs/features/{feature}/SPEC.md` и `docs/PROJECT_ENV.md`. |
| **04** | **Skeleton Writer** | `.ai/rules/skeleton-writer.md` | `FAST_EXECUTION` | Генерация DTO, интерфейсов и заглушек по Секции 0 плана. |
| **05** | **Test Writer** | `.ai/rules/test-writer.md` | `STRICT_CODEGEN` | Написание точных падающих модульных и компонентных тестов по Секции 1 плана. |
| **06** | **Code Writer** | `.ai/rules/code-writer.md` | `STRICT_CODEGEN` | Реализация бизнес-логики до прохождения модульного контрольного этапа. |
| **07** | **Integration Test Writer** | `.ai/rules/integration-test-writer.md` | `STRICT_CODEGEN` | Создание Docker-backed DB/Flyway/HTTP-набора и классификация отказов интеграционного контрольного этапа. |
| **08** | **Integration Code Writer** | `.ai/rules/integration-code-writer.md` | `STRICT_CODEGEN` | Исправление продуктового кода и инфраструктуры при неизменяемом Integration/E2E-наборе. |

Роль **Planner** (`.ai/rules/planner.md`, профиль `REASONING_HEAVY`) выполняет предпайплайновое выявление требований и формирует `docs/PRD.md`; она не входит в нумерованные шаги 01–08.

## 3. Правила и критерии подбора моделей

Примеры классов моделей служат ориентирами, а не жёстким ограничением. IDE, оркестратор или оператор выбирает наиболее актуальную доступную модель, соответствующую характеристикам назначенного профиля.

### 3.1. Требования к свойствам моделей

| Профиль | Минимальный класс и требуемые возможности | Примеры классов моделей |
|---|---|---|
| **`REASONING_HEAVY`** | Флагманские модели с глубоким рассуждением, большим контекстным окном и сильным системным анализом. | Модели старших классов рассуждения семейств OpenAI, Claude, Gemini и DeepSeek. |
| **`STRICT_CODEGEN`** | Специализированные кодовые или актуальные передовые модели с высокой точностью соблюдения синтаксиса и контрактов. | Старшие кодовые модели семейств Claude, OpenAI, Qwen и DeepSeek. |
| **`FAST_EXECUTION`** | Легковесные высокоскоростные модели с низкой задержкой для детерминированной генерации по шаблону. | Быстрые модели семейств OpenAI, Claude, Gemini, Qwen и Llama. |

### 3.2. Локальное переопределение IDE (`.ai/agent-config.local.md`)

Для локальных настроек разработчика или команды может быть создан необязательный файл `.ai/agent-config.local.md`, добавленный в `.gitignore`.

Если файл существует, IDE или оркестратор считывает из него точные имена моделей:

```markdown
# Локальные переопределения моделей, игнорируемые Git

[REASONING_HEAVY]
provider = "auto"
preferred_model = "current-best-reasoning"

[STRICT_CODEGEN]
provider = "auto"
preferred_model = "current-best-coder"

[FAST_EXECUTION]
provider = "auto"
preferred_model = "current-best-fast"
```

Если `.ai/agent-config.local.md` отсутствует, IDE сопоставляет профили `REASONING_HEAVY`, `STRICT_CODEGEN` и `FAST_EXECUTION` с лучшими доступными моделями соответствующих категорий.

## 4. Операционные инструкции для агентов IDE

Перед началом фазы агент сообщает рекомендуемый профиль и выбранную модель. Например:

> `**[tdd-planner]**: Активный профиль: REASONING_HEAVY (рекомендуемая модель: текущая старшая reasoning-модель)`
